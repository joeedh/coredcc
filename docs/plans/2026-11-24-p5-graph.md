- Status: draft, not pressure-tested.

- Architecture: §7, §14 (P5, P5b). Prior art: `docs/research/prior-art.md`, faberforge

P5 also needs small changes outside its own module. They are its step 1, so conflicts show
up early:
- `base/runtime.h`: the version counter and the evaluation scope.
- `api/change_bus.h`: a listener.
- `api/resolve.cc` and `command/executor.cc`: Busy during an evaluation.
- `lib/`: `LibraryPin`, and `destroyFromHistory` respecting pins.
- `bind/facades.cc`: reads are Busy inside a kernel (step 6).

## Facts in the code that shape the design
- **`destroyFromHistory` ignores pins** (`lib/library.cc`). It checks only Strong users.
  A payload that aliases a block's data would dangle when the history drops a delete,
  because only `collect()` treats pins as roots.
- **`Library` has no way to tell a pin holder that it is gone.** A payload that outlives
  its Library would call `unpin` on freed memory.
- **The script facades decide by slot name.** `facades.cc` allows `setValue` and `invoke`
  when the innermost foreign slot is called `exec`, whatever the interface. A node slot
  named `exec` would be allowed to write the document.
- **`ChangeBus::notify` only queues** for the next `flush()`. Nothing sees a change at once.
- **`setValue` calls the member's `update` hook, then notifies.** `SetProperty`'s undo and
  redo go through `setValue`, so they run the hooks too.
- **A settable Pointer member may target another owner only if the target is that owner's
  root struct**, and one inside its own owner needs an `address` callback
  (`resolve.cc`, `Walk::enter`).
- **An item of a collection may carry its own struct type**, with no declared candidates.
  A `refine` pointer needs its candidates when the struct is registered, and structs are
  immutable after that.
- **Copying a Mat4 `PropValue` always allocates** (an out-of-line `Heap` of a string, a
  StableRef and 16 doubles), and litestl's allocator takes a mutex.
- **Runtime extensions are destroyed in reverse order of creation.** `ForeignBindings` is
  usually created late, so it goes first.
- **Pointer values have no literal form** (`command/literal.h`), so an invocation string
  can't name a graph. Scripts need facades for graph edits.
- **faberforge** copies values along edges, pushes dirty flags and checks for cycles at
  execution. Its groups are stubs. Nothing there is reused.
- **ubertopo's survey** recommends verifying traces with early cutoff, keyed element
  memoization in foreach, and structured iteration as a node whose body is a graph. This
  plan does these three. Content-addressed caches stay out.

## Versions and evaluation scope (`base/runtime.h`)
```cpp
/** Monotonic, never 0, never stored in a file or a snapshot. */
uint64_t Runtime::nextVersion();
uint64_t Runtime::version() const;       // the last one issued
/** nextVersion(), recorded as an edit: something an evaluation may depend on changed. */
uint64_t Runtime::touch();
uint64_t Runtime::lastEdit() const;
/** True while a graph is evaluating: setValue, the executor and graph edits are Busy. */
bool Runtime::evaluating() const;
class EvaluationScope;                   // RAII; nests only inside the evaluator
```
- **Every stamp comes from this counter.** Undo, redo and restore stamp fresh versions;
  they never put an old one back. So equal versions imply the same state.
- **Deviation from §7:** a def keeps no list of its instances, and there is no
  `updateGeneration`. Instances compare stamps when they are pulled.
  - Nothing has to be registered, unregistered or walked on an edit.
  - Hosts learn that something changed from the ChangeBus and `rt.lastEdit()`.

## Values and payloads (`graph/value.h`, `graph/payload.h`)
- **`GraphValue`** is a tagged value: the PropValue types except Pointer and Flags, plus
  Payload. Up to 16 doubles are stored inline, so numeric values never allocate; a string
  or payload is one pointer.
  - `fromProp(PropValue)` and `toProp()` convert at the API boundary.
  - `==` is bitwise for floats (as PropValue's is), and by pointer for payloads unless the
    payload type gives an `equal`.
- **`Payload`** is an intrusively refcounted, immutable heavy value, held by `PayloadRef`.
  ```cpp
  template <class T> PayloadRef makePayload(Runtime &rt, PayloadType type, T value);
  template <class T> const T *PayloadRef::get(PayloadType type) const;  // null on mismatch
  template <class T> T *PayloadRef::mutate();   // copies unless this is the only reference
  void PayloadBuilder::alias(Library &lib, BlockHandle h);  // host pin for the payload's life
  ```
  - The type is checked by a hashed id, never RTTI.
  - The refcount isn't atomic. References are made and dropped on the main thread only;
    a kernel's `parallel_for` body may read `const T &`. Debug builds check the thread.
- **`LibraryPin`** (`lib/pin.h`) is a move-only RAII pin. It holds a weak token from the
  Library, so releasing it after the Library is gone does nothing.
- **`destroyFromHistory` on a pinned block** marks it doomed instead of destroying it. It
  stays InHistory, and is destroyed when the last pin goes, or at `endNoCollect` if that
  happens during an evaluation.
  - `restoreFromHistory` clears the mark.
  - It returns ok, because the caller (a discard) has nobody to report to.
- **What aliasing doesn't do:** a pin keeps memory alive. It doesn't stop the owner from
  editing it. Staleness is handled by block dependencies (below), and code that edits a
  block's data in place must call `ChangeBus::notify(owner)`, as it already must.

## Socket types (`graph/socket_type.h`)
- **`SocketTypeRegistry`** (a Runtime extension). An entry has a name, a value type, the
  default, a `PropertyDef` used for unlinked inputs, and for payloads the payload type.
  - Built-ins: `bool`, `int`, `float`, `vec2/3/4`, `mat4`, `quat`, `string`, `enum`, and
    `elements` (a payload, for foreach).
  - `addPayloadType(name, PayloadOps)`; `PayloadOps` is an optional `equal` and an optional
    `bytes(const T &)` for memory reports.
  - **Deviation from §7:** there is no per-type copy, hash or serialize. GraphValue copies
    and compares itself, nothing hashes values, and only literals are saved (by P2's value
    bytes). Payload sockets have no literal: an unlinked one is a null payload.
- **Conversions on links:** `addConversion(from, to, fn)`.
  - Built in: between bool, int and float, and float to vec2/3/4. Float to int truncates
    and saturates, and NaN becomes 0.
  - A link between types with no conversion is TypeMismatch.

## Node types (`graph/node_type.h`)
```cpp
struct GraphKernel : IfaceRef {                      // "coredcc::GraphKernel"
  Status evaluate(NodeExecContext &ctx) const;       // the only slot
};
NodeTypeDef("math.add").uiName("Add")
    .input("a", "float", PropValue::ofFloat(0)).input("b", "float", ...)
    .output("sum", "float")
    .param(PropertyDef::enumProp("mode")...)
    .kernel("math.add#kernel", own<GraphKernel>(...));
```
- **The slot is `evaluate`, not `exec`**, because of the facades' slot-name rule.
- **One kernel object per node type.** It has no per-node state. `NodeExecContext` gives:
  - inputs by index or name, and whether each is linked;
  - outputs to set, each checked against its socket's type;
  - params, and `paramBlock(name)` for Pointer params;
  - `useBlock(BlockHandle)`, which returns the data and records a dependency;
  - the Runtime, and the instance's `userData()`. It doesn't give a Context.
- **Purity:** a kernel reads only through its NodeExecContext and writes only its outputs.
  `setValue`, `run`, `undo`, `redo`, graph edits and `collect()` are Busy while it runs.
  A kernel that writes a block's C++ data directly can't be caught.
- **`NodeTypeRegistry`** (a Runtime extension) checks names, socket types, param defs and
  duplicates. It registers two ApiStructs per type (see "Datapath"). Adding a type calls
  `rt.touch()`, so nodes that were waiting for it recompile.
- **Pointer params** may only target blocks (their root struct). Collection params are
  rejected at registration.
- **Built-in types:** `graph.input`, `graph.output`, `graph.group`, `graph.foreach`,
  `value.*`, `math.float` (an op enum), `vec.combine`, `vec.separate`, `mat4.multiply`. No
  larger library of nodes is in scope.

## GraphDef (`graph/def.h`)
```cpp
class GraphDef {
  explicit GraphDef(Runtime *rt);         // standalone, or the data of a coredcc.GraphDef block
  Result<NodeId> addNode(std::string_view type, NodeId id = {});   // id: revive
  Status removeNode(NodeId);              // and its links
  Result<LinkId> link(SocketRef from, SocketRef to);    // replaces the input's link
  Status unlink(LinkId);
  Status setLiteral(NodeId, std::string_view input, const PropValue &);
  Status setParam(NodeId, std::string_view name, const PropValue &);
  Status setGroup(NodeId, BlockId def);
  Result<int64_t> addInterface(InterfaceSide, name, socketType); ...remove, move, setType
  void foreachRef(RefVisitor &);
};
```
- **`NodeId`, `LinkId` and interface ids** are positive int64 values from counters in the
  def. The counters never go back, so an id is never reused in a def, undo included. They
  are the `[#handle]` keys of datapaths.
- **A node holds** its id, type name, label, position, params, literals, the version stamps
  below, and a snapshot of its sockets. Nodes are separate allocations, so pointers to them
  are stable while the node exists.
- **The socket snapshot** is what keeps links meaningful when the truth isn't available:
  a node type that isn't registered, or a group def that is deleted. It is refreshed when
  the truth is available, and isn't undoable data.
- **Links name sockets by key:** an identifier for a node type's socket, `#<id>` for an
  interface socket, so renaming or reordering an interface breaks nothing.
- **A link to a socket that doesn't exist is kept and ignored,** and listed in
  `def.diagnostics()`. So removing an interface socket edits only its own def, and undoing
  the removal brings the links back with no edits to other blocks.
- **One link per input.** Multi-input sockets are out.
- **`graph.output`:** at most one per def. Any number of `graph.input` nodes.
- **Stamps:**
  - per node: `paramVersion` (params and literals), `inputsVersion` (its links, its group
    ref, its type);
  - per def: `structureVersion` (nodes, links, interface). It keys the cached topology
    (key-to-index resolution and adjacency).
- **References:** a group's def and Pointer params are `RefCell`s of kind OptStrong in the
  node, enumerated by `foreachRef`. Pointer params are never stored as StableRefs.
  A NodeTypeDef may make a Pointer param Weak instead (P5c's generated nodes need this).
- **Edits during an evaluation are Busy.** Each edit checks `rt.evaluating()`.

### Cycles and recursion
- **Within a def, `link` rejects cycles.** The check walks upstream from the source,
  through groups, at the level of single outputs: a group's output depends only on the
  group inputs its interior really reaches. Treating a group as one unit would reject the
  setups P5c needs (one user graph that reads object A and drives object B).
- **`setGroup` rejects recursion**: a def that reaches itself through group refs.
- **An edit inside a def can create a cycle in a def that uses it.** That edit is allowed.
  The evaluator finds it.
- **The evaluator doesn't rely on either check.** Remaps, restores and loads bypass them.
  - A socket met while already in progress fails with "cycle: a -> b -> a", on every node
    of the loop it found. Which loop is reported depends on where the pull started; which
    sockets fail doesn't.
  - A group whose def is already among its ancestors fails as recursive. Nesting deeper
    than 64 is OutOfRange.

### Block type, provider and commands
- **`coredcc.GraphDef`** is a block type of the built-in client. Its provider returns the
  GraphDef, enumerates its refs, and deletes it.
- **Deleting a def in use:** group refs are nullable, so `core.block.delete` doesn't
  cascade. Group nodes keep their sockets and links, and evaluate to a NotFound error
  naming the def. Undo of the delete makes them work again.
- **Edit operations** are recorded as a list of `GraphOp`s with their inverses (the removed
  node's data, the replaced link, the moved interface entry).
  - Every apply and every revert stamps fresh versions, notifies the ChangeBus and bumps
    its epoch for structural changes.
  - The command finds the def by BlockId each time. If it isn't Live, undo sets the sticky
    error and redo fails.
  - A removed node's data lives in the history, where `foreachRef` can't see it. So the
    command holds history pins on the blocks it references until the discard, as
    `SetProperty` does.
- **Commands** (`registerGraphCommands`), each with a Pointer input `graph`:
  - `graph.create(name)`, which uses CreatedBlocks;
  - `graph.node.add(graph, type, x, y)`, output `node`; `graph.node.remove(graph, node)`;
  - `graph.link(graph, fromNode, fromSocket, toNode, toSocket)`, output `link`;
    `graph.unlink(graph, link)`;
  - `graph.interface.add`, `.remove`, `.move`, `.setType`.
  - Params, literals, labels, positions and the group def are set through datapaths.
- **Many edits in one undo step:**
  `runGraphEdit(ctx, BlockId def, name, fn(GraphEdit &))`. A failure inside `fn` reverts
  what it did.

### Datapath
- `coredcc.GraphDef`: `name` (read-only until P2's rename), `nodes` (by `[#id]`, or by label
  when it is unique), `links`, `inputs` and `outputs` (the interface).
- `GraphNode` has `type`, `label`, `position` and `sockets`. Each node type registers
  `GraphNode:<type>`, whose parent is `GraphNode`, and which adds a fixed pointer `params`
  to its own struct `GraphParams:<type>`. The collection's items carry the struct.
  - Putting params in their own struct means a param can have any name.
  - A node of an unregistered type shows as a plain `GraphNode`.
- `sockets["a"].value` is an unlinked input's literal, one struct per socket type.
- **Tagging:** the accessors call `GraphDef::setParam`, `setLiteral` and `setGroup`, which
  stamp the node. Every instance sees it on its next pull. Stamping in the setters rather
  than only in `update` hooks means C++ callers can't forget it.

## Instances and evaluation (`graph/instance.h`, `graph/evaluator.cc`)
```cpp
class GraphInstance {
  GraphInstance(Runtime *rt, Library *lib, GraphSource def);   // a BlockId, or a GraphDef *
  /** Pulls the interface outputs named. One Status per output; the call itself fails only
   * for Busy, a pending sticky error, or a def that isn't available. */
  Status evaluate(std::span<const std::string_view> outputs, Vector<Status> &results);
  const GraphValue *value(std::string_view output) const;      // null if it has an error
  const GraphValue *lastGood(std::string_view output) const;   // for display
  Status setInput(std::string_view name, GraphValue v);        // external input
  Status evaluateSocket(const SocketPath &p, const GraphValue **out);  // any socket
  Status setOverride(const SocketPath &input, GraphValue v);   // per instance
  Status clearOverride(const SocketPath &input);
  NodeReport report(const NodePath &) const;   // state, Status, origin, exec count, time
  void retry();      // runs failed nodes again
  void clear();      // drops caches, and so payloads and pins
  void setUserData(void *);
};
```
- **An instance is a plain C++ object, not a block.** The client owns it, and destroys it
  before the Runtime. It resolves its def on every call, so a deleted def is an error and
  not a dangling pointer. Payload pins survive the Library safely (LibraryPin).
- **State per node:** outputs, `lastEval` (the counter when its kernel started), one
  `changedAt` per output, its Status, its block dependencies, and the last pass that
  verified it. State is keyed by NodeId and synced when `structureVersion` moves.
- **Groups have no cache of their own.** A read of a group's output continues in the child
  instance, and a read of a `graph.input` in the child continues in the parent, through an
  explicit stack of frames. Children are created when first pulled.
- **No native recursion** over nodes or groups, so depth doesn't cost stack. Kernels run
  from the loop.
- **A node runs when** it has never run, or any of these is newer than its `lastEval`:
  `paramVersion`, `inputsVersion`, its type's registration, an input's source `changedAt`,
  the group link that leads to that source, an external input or override, or a block
  dependency. Otherwise its outputs are kept.
- **Early cutoff:** an output equal to its old value keeps its `changedAt`.
- **Early out:** if `rt.lastEdit()` and the Library's epoch haven't moved since an output
  was verified, `evaluate` returns at once.
- **Only sources of the requested outputs are visited.** Within a node all inputs are
  needed; lazy inputs (a Switch that pulls one branch) are out.

### Block dependencies
- `useBlock` and `paramBlock` record the block, whether it was Live, and its version.
- `GraphSystem` (a Runtime extension) keeps a version per used block. A new
  `ChangeBus::addListener` calls it at once on `notify(Block owner)`, and it stamps that
  block with `rt.touch()`.
- When the Library's epoch moved, each recorded dependency's liveness is compared again.
- **Two rules for other phases:** P2's snapshot restore calls `notify(owner)` for each
  block it restores. P3's `Invalidation` calls it when a block's data changes.

### Errors
- **Outputs are committed only if the kernel succeeds.** It writes to scratch values, so a
  failing kernel never leaves half its outputs new.
- **A failed node:** its outputs are in error, and `value()` is null. `lastGood()` still has
  the old values, and nothing downstream reads them.
- **Downstream nodes don't run.** They are in state InputFailed, with the origin's path and
  message. Outputs that don't depend on the failure evaluate normally.
- Going into or out of error, or failing with another message, moves `changedAt`.
- **A failed node isn't run again** until something it depends on changes, or `retry()`.
- A kernel that returns ok without setting every output fails with Internal, naming the
  output. So does one that sets a value of the wrong type.
- A sticky error left by a kernel becomes that node's error. One that is pending before
  `evaluate` is FailedPrecondition, as in `collect()`.
- **`evaluate` holds `beginNoCollect`** on its Library. `evaluate` from inside a kernel is
  Busy. `evaluate` inside a command's `exec` is allowed.

### Parallel evaluation
- **v1 is serial, on the main thread.** A native kernel may call `parallel_for` on its own
  data. Foreign kernels are thread-affine, which serial evaluation satisfies.
- Running independent nodes in parallel is deferred (§14). What it would need: atomic
  payload counts with releases queued to the main thread, per-node error slots instead of
  the Runtime's sticky error, and a thread-affine queue. Nothing in the public API above
  has to change for it.

## Foreach (`graph/foreach.h`, P5b)
- **`graph.foreach`** has a group ref. Its inputs are `elements` plus the def's other
  inputs, which are the same for every element. Its outputs are `elements` payloads, one
  column per interface output.
- **`elements`** is a payload: int64 keys, and columns of GraphValues named after interface
  inputs. A column missing for an input uses the broadcast value. Duplicate keys are
  InvalidArgument.
- **The pool** is keyed by element key, per foreach node and per instance.
  - A key that is absent from the new table is evicted after a successful run.
  - `maxInstances` (a param, default 4096) caps it. Past the cap the least recently used
    are dropped; elements that don't fit run in one reused transient instance.
- **Incremental:** an element's inputs are compared with its last ones, so editing one
  element runs one element.
- **A failing element** fails the foreach node with its key and the interior origin. The
  other elements' caches stay.
- Elements run in table order, and the result never depends on the pool's state.
- Nested foreach works. Simulation and repeat zones are out.

## What P5c (the scene evaluator) uses
P5c is a client of the API above. It needs, and gets:
- **A generated graph outside the user's library:** a standalone `GraphDef` with the direct
  edit API. It has no block, no undo and no ChangeBus owner. Its owner keeps alive what its
  refs point to, so it uses Weak Pointer params plus `useBlock`.
- **Incremental regeneration:** add, remove and relink per object. An edit is O(degree);
  the topology is rebuilt once per evaluation after edits, O(nodes + links).
- **A generated node type with host data:** a kernel that reads the object through
  `paramBlock`, and the evaluator through `userData()`.
- **User graphs** as group nodes in the generated graph.
- **Interior sockets:** a group's socket key may be `@<node path>.<socket>`, for example
  `@7.value` or `@3/7.value`.
  - As an output, it reads an interior node's socket. This connects an **output adapter** in
    a user graph to a generated node's override input.
  - As an input, it overrides an interior node's input for that group. This feeds a world
    matrix to an "object info" node in a user graph.
  - Commands refuse such keys in user defs; the direct API accepts them.
- **Listing adapters:** `GraphDef::forEachNode(flag)`, with `NodeTypeFlags::OutputAdapter`
  for the generator. P5 ships the flag; P5c ships the adapters.
- **Output-level dependencies,** so "A drives B and C drives A through one user graph" isn't
  a cycle.
- **The apply phase:** `evaluateSocket` on every transform node, then `value()`; on an error
  `lastGood()`.
- **External inputs:** time and the frame as interface inputs through `setInput`.

A test writes a 100-line stand-in evaluator against this list (parents, one driver, one
adapter). It is the check that the list is complete.

## Bindings (`bind/graph_facades.h`)
- **Script node types:** `newNodeType(id)`, `nodeTypeInput/Output/Param`, and
  `registerForeignNodeType(ctx, def, kernelHandle, slots)`. The kernel object is made in
  TS; C++ keeps its handle in `ForeignBindings` (as `keepFactory` does), and the registry
  holds a non-owning kernel. So the order in which the two extensions die doesn't matter.
  The `core.` and `graph.` namespaces are reserved.
- **Inside a kernel:** `nodeInput(ctx, name)`, `nodeParam(ctx, name)`,
  `nodeOutput(ctx, name, value)`, and `nodePass(ctx, input, output)` for payloads and types
  scripts can't write (Mat4). Scripts see payloads only as something to pass on.
- **Datapath reads from inside a kernel are Busy** too. They would be dependencies the graph
  can't see.
- **Editing:** `graphCreate`, `graphAddNode(ctx, graphPath, type, x, y)`,
  `graphRemoveNode`, `graphLink`, `graphUnlink`, `graphAddInterface`. Each resolves the
  graph path and runs the command, because Pointer inputs have no literal form.
- **Evaluating:** an owned bound `ScriptGraph` made by `graphInstance(ctx, graphPath)`:
  `setInput`, `evaluate(output) -> ValueResult`, `errorText`. Hosts keep it in their session
  object, as they do the Context.
- The TS layer gets `defineNodeType` in the shape of its existing command helper.

## Serialization (last step, on P2's slots)
- The payload holds a format version, the three counters, the interface, the nodes (id, type
  name, label, position, params and literals by name) and the links by key. P2's tagged
  value bytes are self-describing, so a node of an unknown type keeps its params.
- References go through the block's ref list, never as a BlockId in the payload (§8a).
  **Required of P2's slots:** the serializer can turn a RefCell into an index in the block's
  ref list, and the reader can turn it back. If P2's API differs, this section changes.
- Socket snapshots are saved. Versions, topology and caches aren't.
- **Reading is bounded:** counts are checked against the remaining bytes, duplicate ids and
  links to unknown nodes are errors, and counters below an existing id are raised. A bad
  payload is an error, with nothing half-built.
- `duplicate` copies the def and maps group refs through the IdMap.
- Loading into an existing def (a snapshot restore) stamps everything with fresh versions.

## Tests
- **`tests/graph/test_graph_random.cc`**, seeded, scaled by `COREDCC_TEST_SCALE`:
  - Random edits over several defs that use each other as groups: nodes, links, params,
    literals, interface changes, group changes, deleting and restoring defs, node types that
    fail on some inputs, direct edits of used blocks with `notify`. Undo and redo are mixed
    in, and the redo side is truncated.
  - After each batch, two long-lived instances pull random outputs. The results (value, or
    error origin and message) must equal those of **a naive recursive evaluator written in
    the test** that shares no code with the engine: no caches, no topology.
  - A second pull runs no kernel. A pull after edits runs no more kernels than a fresh
    instance would.
  - Undoing everything gives a def equal to the first one (ids and links), and redoing
    everything gives one equal to the last.
- **Mutation checks,** run one at a time and reported one at a time. Each must make a test
  fail: not stamping on undo; not stamping `inputsVersion` on link; comparing `<` as `<=`;
  ignoring the group link's version; keeping `changedAt` on an error transition; reading
  `lastGood` downstream; not comparing liveness; skipping the pin in a remove command;
  evicting before the foreach succeeds.
- **Lifetimes:** payload after its Library; instance after its def; destroying a pinned
  InHistory block; `collect` during an evaluation; a GC after undo of a removed node, in
  quarantine mode.
- **Errors, cycles and recursion:** a cycle created by an inner edit; recursion introduced
  behind the checks by writing the RefCell; 63, 64 and 65 nested groups; a 100,000-node
  chain (no stack overflow on a 1 MB stack).
- **Reentrancy:** from a kernel, `setValue`, `run`, `undo`, an edit, `collect` and
  `evaluate` are all Busy, natively and from a script.
- **Foreach:** random table edits against the naive evaluator; the cap; duplicates.
- **Scripts:** the fake dispatcher, and a node type written in TS in the wasm-st spike,
  including one that throws.
- **Fuzz:** `deserialize` on mutated payloads.
- **Benchmarks** (`tests/graph/bench_graph.cc`, not a ctest): a 10,000-node mat4 chain, full
  and after one edit; an unchanged pull; 1,000 instances of a 100-node group; foreach over
  10,000 elements with one edited. Results go in this plan. The target, to be checked: an
  unchanged pull under 1 µs, and re-verifying 10,000 nodes after one edit under 2 ms, in
  Release.

## Order of work
Each step is a commit that passes the gate (4 native presets, wasm-st-debug).
1. Runtime versions and evaluation scope, ChangeBus listener, Busy checks, LibraryPin,
   `destroyFromHistory` with pins.
2. Payloads, values, socket types, node types, kernels.
3. GraphDef (standalone), topology, cycle and recursion checks.
4. GraphInstance: pull evaluation, groups, errors, external inputs, block dependencies; the
   random test on the direct API.
5. The block type, datapath, commands, undo; the random test with undo and redo.
6. Interior sockets, overrides, the P5c stand-in test. Bindings and the TS test.
7. P5b foreach.
8. Serialization, after rebasing onto P2's first step.
9. Benchmarks, docs, mutation checks. Then the API review ("graph" in the task list).

## Exit criteria
- The random test agrees with the naive evaluator for at least 1,000,000 operations in each
  compiler's Release build, and at the default scale in every gate.
- Every mutation check fails a test.
- A node type written in TS evaluates in wasm-st, and its errors reach the caller.
- The P5c stand-in works using only the API in "What P5c uses".
- wasm-mt builds and passes its tests.
- Benchmark results are recorded.

## Claims to falsify
1. `destroyFromHistory` destroys pinned blocks today, and deferring it breaks no existing
   test or command (DeleteBlock, CreatedBlocks, SetProperty).
2. The facades' slot check goes by name alone, so a slot named `exec` on any interface may
   call `setValue`, and one named `evaluate` may not.
3. All datapath writes, undo and redo included, go through `setValue`, the accessor and
   `ChangeBus::notify`; so a listener in `notify` sees every datapath change to a block.
4. A fixed `params` pointer on a per-type item struct resolves, canonicalizes and undoes
   through `nodes[#id].params.x`, and a StableRef to it survives removing and re-adding the
   node with the same id.
5. A cross-owner settable Pointer param works without an `address` callback, and its undo
   works.
6. The non-owning kernel plus handles kept by ForeignBindings is safe in either order of
   extension destruction.
7. Stamps alone find every stale node, with no list of instances. In particular: swapping a
   link to an older source; undoing that; changing a group's def to one with older stamps;
   a block deleted and restored between two pulls; an element that leaves and returns.
8. With early cutoff, a kept `changedAt` can never hide a change from a node that last ran
   before it.
9. Transparent groups with output-level dependencies terminate, and find every cycle, when
   groups call in and out of each other several times in one pull.
10. Which sockets fail in a cycle doesn't depend on where the pull started.
11. History pins on the blocks referenced by removed nodes are enough: no undo or redo
    reaches a freed block, across purge, budget trimming and redo truncation.
12. Keeping dangling links makes every interface edit local to one def, undo included.
13. Nothing in base, api, command or lib has to know about graphs beyond step 1's hooks.
14. `GraphValue` inline storage is worth it: measure against PropValue plus a payload.
15. P5c's list is complete: the stand-in test needs nothing else.
16. A `Busy` in `setValue` during an evaluation breaks no legitimate path, such as a command
    that evaluates inside `exec`.

## Risks
- **P2's slot API isn't final.** Only step 8 depends on it.
- **P3 and P5 both edit `api/`.** Step 1's changes are a few lines and come first.
- **The output-level cycle walk may be slow** in large defs with deep groups: it is a walk
  per link. If so, cache reachability per def by `structureVersion`.
- **Memory:** about 150 bytes per output per instance. If foreach at scale is too big, store
  outputs by type.
- **Two sources of truth for sockets** (the snapshot and the real ones). The random test
  includes registering node types late and deleting group defs.

## Out of scope
- Parallel and content-addressed evaluation, cyclic regions, simulation (§14, deferred).
- Lazy inputs, multi-input sockets, muting, reroutes, node frames, copy and paste, making a
  group from a selection.
- Payloads created by scripts, and scripted payload types (P6).
- The scene evaluator, adapters and generated transform nodes (P5c).
- A node editor UI.
