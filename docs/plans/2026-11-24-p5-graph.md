Decided after the pressure tests:
- **Library lifetime is one piece, owned by P2,** in its early shared step: pin kinds,
  deferred destruction of pinned blocks, and a Library token. What P5 needs from it is
  listed below.
- **Immediate change notification is one piece, owned by P5,** in its step 1, which depends
  on nothing from P2 or P3 and merges early: `ChangeBus` listeners, notifying before the
  `update` hook, and `notifyAll()`.
  - P2's load, append, placeholder filling (adoption) and rename call `notify(owner)` for
    each block they touched. Opaque `SnapshotProvider` restores call `notifyAll()`.
    (P2 cut `BlockSnapshotUndo` and `replaceData`, 2026-11-24.)
  - P3's `Invalidation` calls `notify(owner)` when a block's data changes.

### What P5 needs from P2's library piece
P2's published API (`be2be34`) has 1 to 7, with the differences noted here.
1. **A Library token:** a weak `LibraryRef` with `Library *get()`, null once the Library is
   being destroyed. `LibraryPin` (RAII, move-only) is built on it and does nothing after
   that.
2. **`destroyFromHistory` on a block with Host pins** returns ok and marks it doomed.
   - It leaves the `byId_` index at once, so `find` doesn't see it, and `createWithId` and
     `reviveAs` with its id succeed.
   - It is destroyed when its last Host pin goes, or at `endNoCollect` if that happens
     inside a no-collect scope or a sweep.
   - Its strong refs keep their targets alive until then (it is still a GC root).
   - The check for Live or Detached Strong users runs again at that time. If one exists, the
     block goes back to InHistory under its id if that is still free. Otherwise P2 destroys it:
     the user's ref names the other record.
3. **Errors from a deferred destroy** (a foreign `destroy` that throws) go to the Library,
   which returns them from its next `collect()`. They don't become the Runtime's sticky
   error, or the next unrelated command would fail.
4. **`PinKind {Host, History}`.** P5 uses History in undo records and Host in payloads. Pins
   are released on the main thread only.
5. **`Datablock::stateChanges()`:** a counter bumped by every state transition. Without it, a
   host destroy and restore between two pulls can't be seen.
6. **`attach`, `detach`, `setOverride` and `clearOverride` bump the epoch.** They change
   what `query` answers, and today they don't.
7. **`Library::busy()`:** true while sweeping or collecting. `collecting_` has no accessor.
8. `BlockTypeInfo::storage`, so `makeAlias` can refuse Transient types. There is no HostOwned
   type until P4; `dataAlive()` covers a host that destroys its data.

## Facts in the code that shape the design
- **`destroyFromHistory` ignores pins** and checks only Strong users. `~Library` and
  `onHostDestroyed` ignore pins too.
- **The script facades decide by slot name.** `slotGate` compares the innermost foreign
  slot's name with a list, whatever the interface. A slot named `exec` may call `setValue`.
- **`ChangeBus::notify` only queues** for the next `flush()`.
- **`setValue` calls the `update` hook, then notifies** (`resolve.cc:710`). `SetProperty`'s
  undo and redo go through `setValue`.
- **A settable Pointer member may target another owner only at that owner's root**, and one
  inside its own owner needs an `address` callback. A self-target is written and only then
  fails, in `SetProperty`'s read-back.
- **A collection item may carry its own struct type** with no declared candidates. A
  `refine` pointer needs its candidates when the struct is registered.
- **ApiRegistry refuses members named `length` and `active`,** and can't unregister.
- **An Enum def without items is invalid.**
- **Copying a Mat4 `PropValue` allocates:** 120 ns, against 3.5 ns for inline storage
  (measured, Release).
- **Runtime extensions are destroyed in reverse order of creation.** `ForeignBindings` is
  usually created late, so it goes first.
- **Pointer values have no literal form,** so an invocation can't name a graph.
- **A ref that changes without `writeRef` or `noteRefsChanged`** leaves `usersOf` wrong, and
  a debug `collect()` fails with "the relations cache is stale" (run).
- **faberforge** copies values along edges, pushes dirty flags and checks for cycles at
  execution. Its groups are stubs. Nothing there is reused.
- **ubertopo's survey** recommends verifying traces with early cutoff, keyed memoization in
  foreach, and iteration as a node whose body is a graph. This plan does these three.
  Content-addressed caches stay out.

## Versions and evaluation scope (`base/runtime.h`)
```cpp
/** Monotonic, never 0, never stored in a file or a snapshot. */
uint64_t Runtime::nextVersion();
/** nextVersion(), recorded as an edit: something an evaluation may depend on changed. */
uint64_t Runtime::touch();
uint64_t Runtime::lastEdit() const;
/** True while a graph is evaluating. */
bool Runtime::evaluating() const;
class EvaluationScope;                   // RAII; only the evaluator and tests open one
```
- **Every stamp comes from this counter.** Undo, redo and restore stamp fresh versions;
  they never put an old one back. So equal versions mean the same state.
- **The instance pulls; nothing is pushed.** A def keeps no list of its instances.

### What is Busy while `evaluating()`
- `setValue`, and through it `setValueUndo` and `writeValue`.
- **Every executor entry point,** checked before anything else: `run`, `runInstance`,
  `runSub`, `undo`, `redo`, `rerunHead`, `beginInteractive`, `commit` and `cancel`.
  - Today's nesting guard (`running() || slotDepth_ > 0`) covers commands' slots. It doesn't
    cover a kernel that runs while an interactive command is open: `undo` would reach
    `cancel`, whose undo would be refused by `setValue` while the record was dropped.
  - `cancel` also gets the check every other call has, that the Context isn't bound to
    another executor. Today it ignores that result and takes the record anyway.
- GraphDef edits, and registering node types, socket types and conversions.
- On any GraphInstance: `evaluate`, `setInput`, `retry` and `clear`.
- `collect()` (through `beginNoCollect`).
- `evaluate` itself while the Library is busy (sweeping or collecting).
- **Destroying a GraphInstance while it evaluates** aborts (CDCC_CHECK) in C++. A script's
  `ScriptGraph` is shared: disposing it inside a kernel closes it, and it is freed when the
  evaluation ends.
- A native kernel that writes a block's C++ data directly, or calls `Library` functions,
  can't be stopped. Such a write still notifies if it follows the rules.

## Values and payloads (`graph/value.h`, `graph/payload.h`)
- **`GraphValue`** is a tagged value: Bool, Int, Float, Vec2-4, Mat4, Quat, String and
  Payload. Up to 16 doubles are inline (136 bytes), so numeric values never allocate.
  - `fromProp(PropValue)` and `toProp()` convert at the API boundary.
  - `==` is bitwise for floats, as PropValue's is, and by pointer for payloads unless the
    type gives an `equal`.
  - **No Enum sockets.** Enums are params. A socket type has no place for enum items, and
    links between two enums would need them compared.
- **`Payload`** is an intrusively refcounted, immutable heavy value, held by `PayloadRef`.
  ```cpp
  template <> struct PayloadTraits<MyMesh> { static constexpr const char *name = "my.Mesh"; };
  template <class T> PayloadRef makePayload(T value);
  template <class T> const T *PayloadRef::get() const;   // null on another type
  template <class T> T *PayloadRef::mutate();            // the only ref: in place; else a copy
  template <class T> Result<PayloadRef> makeAlias(T view, Library &lib, BlockHandle block);
  ```
  - The type is `PayloadTraits<T>::name`'s hash. Registration stores litestl's `typeKey`, so
    two C++ types under one name are rejected.
  - The refcount isn't atomic. References are made and dropped on the main thread; a
    kernel's `parallel_for` body may read `const T &`. Debug builds check the thread.
- **An aliasing payload** (`makeAlias`) holds views into a block's data and a Host
  `LibraryPin` for each block it aliases.
  - `get()` returns null once the Library is gone, or the block is no longer Live or
    InHistory (Detached, or doomed and destroyed). Keep the payload, not the pointer.
  - `mutate()` returns null: it would hand out the user's original data for writing.
  - `makeAlias` is Unsupported for a Transient block type. A host that destroys its data makes
    `get()` null through `LibraryPin::dataAlive()`.
  - The pin is released on the main thread, with the payload's last reference.
  - A pin keeps memory alive. It doesn't stop the owner from editing it; block
    dependencies make the reader stale.
  - A block that owns an instance whose payload aliases that same block pins itself, and is
    never collected. Documented; the client must `clear()` the instance.

## Socket types (`graph/socket_type.h`)
- **`SocketTypeRegistry`** (a Runtime extension): a name, a value type, the default, and for
  payloads the payload type and its `PayloadOps` (optional `equal`, `bytes`).
  - Built in: `bool`, `int`, `float`, `vec2/3/4`, `mat4`, `quat`, `string`, `elements`.
- **Conversions:** `addConversion(from, to, fn)`. They can't be replaced or removed.
  - Built in: between bool, int and float, and float to vec2/3/4. Float to int truncates
    and saturates, and NaN becomes 0.
  - A link with no conversion is TypeMismatch at edit time. One that appears later (an
    interface type change) is an evaluation error on the reading node.

## Node types (`graph/node_type.h`)
```cpp
struct GraphKernel : IfaceRef {                      // "coredcc::GraphKernel"
  Status evaluate(NodeExecContext &ctx) const;       // the only slot
};
NodeTypeDef("my.scale").uiName("Scale")
    .input(PropertyDef::floatProp("factor").range(0, 10))    // type, literal, UI metadata
    .payloadInput("mesh", "my.Mesh")
    .output("out", "my.Mesh")
    .param(PropertyDef::enumProp("mode").item(...))
    .kernel("my.scale#kernel", own<GraphKernel>(...));
```
- **An input is a `PropertyDef`,** so literals have ranges, units and subtypes. Its kind
  gives the socket type. Payload inputs have no literal; unlinked, they are null.
- **Registration checks everything first,** then registers the structs: names are
  identifiers, unique, and not `length` or `active`; socket types exist; Enum defs have
  items; Pointer params name a target struct; there are no Collection params. A failure
  after that would leave a struct that can't be removed, so nothing can fail after that.
- **One kernel per node type,** with no per-node state. `NodeExecContext` gives:
  - inputs by index or name, and whether each is linked; outputs to set, type-checked;
  - params, and `paramBlock(name)` for Pointer params;
  - `useBlock(BlockId) -> BlockUse {handle, data}`, which records a dependency even when the
    block is absent;
  - `queryBlock<I>(handle)`, which records the answer (table and self) as a dependency;
  - `library()` (const), the Runtime, and the instance's `userData()`. No Context.
- **Purity:** a kernel reads through its NodeExecContext and writes only its outputs.
- **Adding a type** calls `rt.touch()`, so nodes waiting for it recompile.
- **Built-in types:** `graph.input`, `graph.output`, `graph.group`, `graph.foreach`,
  `value.*`, `math.float` (an op enum param), `vec.combine`, `vec.separate`,
  `mat4.multiply`.

## GraphDef (`graph/def.h`)
```cpp
class GraphDef {
  explicit GraphDef(Runtime *rt, Library *lib = nullptr, BlockId self = {});
  Result<NodeId> addNode(std::string_view type, NodeId id = {});   // id: revive
  Status removeNode(NodeId);              // and its links
  Result<LinkId> link(SocketRef from, SocketRef to);    // replaces the input's link
  Status unlink(LinkId);
  Status setLiteral(NodeId, std::string_view input, const PropValue &);
  Status setParam(NodeId, std::string_view name, const PropValue &);
  Status setGroup(NodeId, BlockId def);
  Result<int64_t> addInterface(InterfaceSide, name, socketType); ...remove, move, setType
  void foreachRef(RefVisitor &);
};
```
- **Its home:** a Library, and the block it is the data of. A **standalone** def has no block;
  it may have a Library (needed for groups and Pointer params, FailedPrecondition without).
  - Every edit that adds, drops or changes a RefCell goes through `writeRef` or calls
    `noteRefsChanged` on that Library.
  - Every edit of a block's def calls `notify(OwnerKey::ofBlock(self))`, and bumps the
    ChangeBus epoch for structural ones. A standalone def notifies nobody.
- **Ids** of nodes, links and interface sockets are random 52-bit integers from the
  Runtime's GUID source, retried on a collision in the def. They are the `[#handle]` keys.
  - A counter could be rolled back by a load, and a reused id would make an old StableRef name
    another node.
  - Interface ids are unique across defs, so pointing a group at an unrelated def can't
    reconnect links by accident, and pointing it at a copy does reconnect them.
  - 52 bits fit a JS number.
- **A node holds** its id, type name, label, position, params, literals, stamps, and a
  snapshot of its sockets. Nodes are separate allocations.
- **The socket snapshot** keeps links meaningful when the node type isn't registered or the
  group's def is gone. It is refreshed when the truth is available. It isn't undoable.
- **Links name sockets by key:** an identifier, or `#<id>` for an interface socket.
- **A link to a socket that doesn't exist is kept and ignored,** and listed in
  `def.diagnostics()`. So an interface edit touches only its own def, and its undo brings the
  links back.
- **One link per input.** At most one `graph.output` node per def.
- **Stamps:** per node `paramVersion` (params and literals); per def `structureVersion` (keys
  the topology), `contentVersion` (any edit except labels and positions), and `serial` (one
  per GraphDef object, so a block's data being replaced is seen as another def).
- **References:** group defs and Pointer params are OptStrong `RefCell`s in the node (a
  NodeTypeDef may make a param Weak), enumerated by `foreachRef`. A param whose target is
  the def's own block is InvalidArgument, checked before anything is written.
- Interface sockets can't be renamed into keys (they have none but the id); their type is one
  of the socket types.

### Cycles and recursion
- **Dependencies are per output.** A def's **reach table** says, for each interface output,
  which interface inputs it depends on. It is computed once per def and cached by the
  `contentVersion`s of the defs below it. So nested groups cost a table each, not an
  expansion.
- **`link` rejects cycles within a def,** using plain nodes as all-inputs-to-all-outputs and
  groups by their reach tables. A group isn't one unit: P5c needs one user graph that reads
  object A and drives object B.
- **`setGroup` rejects recursion:** a def that reaches itself through group refs.
- **An edit inside a def can create a cycle in a def that uses it.** It is allowed, and the
  evaluator reports it.
- **The evaluator relies on neither check** (remaps, restores and loads bypass them):
  - Pulling is a depth-first walk with Tarjan's algorithm over socket vertices, pass-through
    sockets (group outputs, interface inputs) included, so a loop with no kernel in it is
    found too. Every vertex on a cycle fails. Its origin is the smallest
    (path, node, socket) of that strongly connected component, and its message names at most
    8 members, so neither depends on where the pull started.
  - A node visits all its inputs even after one has failed, for the same reason.
  - A group whose def is among its ancestors fails as recursive. Deeper than 64 is
    OutOfRange.
- **A budget:** at most `maxFrames` child instances per root instance (default 262,144;
  foreach elements aren't counted, their tables bound them). Past it the whole `evaluate`
  fails with OutOfRange. A chain of defs that each hold two of the next is 2^n.

### Block type, provider and commands
- **`coredcc.GraphDef`** is a block type of the built-in client. Its provider returns the
  GraphDef, enumerates its refs, and deletes it.
- **Deleting a def in use:** group refs are nullable, so the delete doesn't cascade. Group
  nodes keep their sockets and links and evaluate to NotFound, naming the def. Undo of the
  delete makes them work again.
- **Edits** are recorded as `GraphOp`s with their inverses. Every apply and revert stamps
  fresh versions and goes through the def's home.
  - A command finds the def by BlockId each time. If it isn't Live, undo sets the sticky
    error and redo fails.
  - The settable block pointers (`group`, Pointer params) fill P2's `PointerAccessor::cell`, so
    SetProperty's undo keeps links to blocks that aren't Live.
  - **History pins** are taken on every block that a ref removed, added or replaced by the
    command points to, until the discard.
- **Commands** (`registerGraphCommands`), each with a Pointer input `graph`: `graph.create`;
  `graph.node.add` (output `node`) and `.remove`; `graph.link` (output `link`) and
  `graph.unlink`; `graph.interface.add`, `.remove`, `.move`, `.setType`. Params, literals,
  labels, positions and the group def are set through datapaths.
- **Many edits in one undo step:** `runGraphEdit(ctx, BlockId, name, fn(GraphEdit &))`. A
  failure inside `fn` reverts what it did.

### Datapath
- `coredcc.GraphDef`: `name`, `nodes` (by `[#id]`, or by label when unique), `links`,
  `inputs` and `outputs` (the interface).
- `GraphNode` has `type`, `label`, `position`. Each node type registers `GraphNode:<type>`
  (parent `GraphNode`) with fixed pointers `params` and `inputs` to its own structs
  `GraphParams:<type>` and `GraphInputs:<type>`, one member per def.
- Group and foreach nodes have a collection `sockets` instead of `inputs`:
  `sockets[#id].value` is an unlinked input's literal.
- A node of an unregistered type shows as a plain `GraphNode`.
- **Deviation from §7:** stamping is in GraphDef's setters, not in `update` hooks, so C++
  callers can't forget it.

## Instances and evaluation (`graph/instance.h`, `graph/evaluator.cc`)
```cpp
class GraphInstance {
  GraphInstance(Runtime *rt, Library *lib, GraphSource def);   // a BlockId, or a GraphDef *
  /** One Status per socket; the call itself fails only for Busy, a pending sticky error,
   * the budget, or a def that isn't available. */
  Status evaluate(std::span<const SocketPath> sockets, Vector<Status> &results);
  const GraphValue *value(const SocketPath &) const;       // null if it has an error
  const GraphValue *lastGood(const SocketPath &) const;    // for display
  uint64_t changedAt(const SocketPath &) const;
  /** False if a pull might give something new: the edit counter, the Library's epoch or
   * this instance's inputs moved since. Cheap; for a host's redraw decision. */
  bool isCurrent(const SocketPath &) const;
  Status setInput(std::string_view name, GraphValue v);    // an interface input
  NodeReport report(const NodePath &) const;   // state, Status, origin, run count, time
  Status retry();                              // runs failed nodes again
  Status clear();                              // drops caches, and so payloads and pins
  void setUserData(void *);
};
```
- **`SocketPath`** is an interface output by name or id, or (node path, socket) for any socket.
- **An instance is a plain C++ object, not a block.** The client destroys it before the
  Runtime. It resolves its def on every call, and holds the Library through `LibraryRef`.
- **State per node,** keyed by NodeId and checked against the node type; dropped when the
  def's `serial` changes. Groups have no outputs of their own; children are made when first
  pulled, each with a serial from `nextVersion()`.
- **Frames are on an explicit stack,** so depth costs no native stack.
- **During `evaluate`:** `beginNoCollect`, an EvaluationScope, and Host pins on the def
  blocks visited, so a native `destroyFromHistory` in a kernel can't free a def being walked.

### When a node runs: the trace
A run records a trace: everything it read, and the version it saw. A node runs if it has no
trace, or any entry differs now. Entries compare for **equality**, never with `<`.
- `paramVersion`, and the node type's registration stamp.
- **Per input, the resolved source:** following links through groups to the end gives a
  kernel's output (child serial, NodeId, output), a literal (its node), an external input, or
  an error. With it, the chain of socket types crossed (the conversions), and the source's
  `changedAt` (a literal's is its node's `paramVersion`; an interface default's is the def's
  stamp for that entry).
  - This is why an edit that only changes what an input resolves to is seen: removing an
    interface output, `setType`, a conversion or node type registered late. Comparing stamps
    of the path missed those in 17 of 300 runs of a model; the recorded source in none.
- **Block dependencies** (below), and recorded `queryBlock` answers.

Rules:
- **`changedAt`** of an output moves only when its value differs (early cutoff), or it goes
  into or out of error, or its error differs.
- **Resolved sources are memoized per pass,** so a chain of pass-through groups read at every
  hop stays linear.
- **A pass is keyed by** (`rt.lastEdit()`, the Library's epoch, the instance's own edit count),
  sampled when `evaluate` starts. Calls with the same key share it: anything verified under
  the key is returned at once, so 10,000 separate calls cost one walk. A `notify` from a
  kernel moves the key of the next call.
- `setInput` and `retry` move the instance's own count, not the Runtime's.
- **Only sources of the requested sockets are visited.** Within a node all inputs are needed.

### Block dependencies
- A dependency records the canonical BlockId, the handle, the state, `stateChanges()`, and
  the block's version. So these are all seen: absent then present, destroyed and recreated
  under one id, destroyed and restored by the host between pulls.
- **Versions** live in `GraphSystem` (a Runtime extension): one per used block, stamped with
  `rt.touch()` by a ChangeBus listener on `notify`, after making the owner's client
  canonical. `notifyAll()` stamps every block.
- Dependencies are compared when the pass key moved.
- **ChangeBus (step 1):** `addListener(fn(const OwnerKey *))` is called at once by `notify` and,
  with null, by `notifyAll()`. `notifyAll()` also makes every watcher re-read at the next
  flush. A listener may not notify.
- **`setValue` notifies before the member's `update` hook,** so a hook that pulls a graph
  sees the new value.

### Errors
- **Outputs commit only if the kernel succeeds.**
- **A failed node:** its outputs are in error and `value()` is null. `lastGood()` still has the
  old values, and nothing downstream reads them.
- **Downstream nodes don't run:** InputFailed, with the origin's path and message (the first
  failing input, in input order). Other outputs evaluate normally.
- **A failed node isn't run again** until its trace differs, or `retry()`. Nodes on a cycle are
  walked again under each new key.
- A kernel that returns ok without setting every output, or sets a wrong type, fails with
  Internal.
- A sticky error left by a kernel becomes that node's error. One pending before `evaluate` is
  FailedPrecondition.
- `evaluate` inside a command's `exec` is allowed.

### Parallel evaluation
- **v1 is serial, on the main thread.** A native kernel may use `parallel_for` on its own data.
  Foreign kernels are thread-affine, which this satisfies.
- Deferred (§14). It would need atomic payload counts with releases queued to the main thread,
  per-node error slots, and a thread-affine queue. The API above wouldn't change.

## Foreach (`graph/foreach.h`, P5b)
- **`graph.foreach`** has a group ref. Its inputs are `elements` plus the def's other inputs
  (broadcast). Its outputs are `elements` payloads, one column per interface output.
- **`elements`** is a payload: int64 keys, and columns of GraphValues named by interface input.
  Duplicate keys are InvalidArgument.
- **Admission:** the first `maxCached` keys in table order (default 16,384) have cached
  instances; the rest run in one reused transient instance. There is no LRU: a table-order
  scan over an LRU cache smaller than the table hits nothing.
- **Staleness has two levels:**
  1. The foreach node's trace holds the table payload, each broadcast input's source, the
     `contentVersion` and `serial` of every def inside, and the **union of all block
     dependencies** its elements recorded in the last run. Nothing moved: the old columns
     stand, and no element is visited.
  2. Something moved: every cached element is verified by its own trace (its column values are
     compared with its last ones), and every transient element runs again.
- So an edit elsewhere runs no elements, an interior edit runs what it reaches, and one
  changed element in the cached part runs one.
- An absent key is evicted after a successful run, not before.
- **A failing element** fails the node with its key and interior origin. Caches stay.
- Elements run in table order. Results don't depend on what is cached. Nested foreach works.

## Interior sockets (after foreach)
- A group's socket key may be `@<node path>.<socket>`, e.g. `@7.value` or `@3/7.value`.
  - As an output it reads an interior socket. As an input it replaces the interior input's
    link or literal, for that group node only.
- **Cycle checks** extend the reach table per group node with the keys it uses: an overridden
  interior input is an extra input of the def, and its own link no longer counts; an interior
  output is an extra output. The evaluator does the same per frame, so the trace's resolved
  source covers it.
- The direct API accepts them. Commands refuse them in user defs.
- `setOverride` was cut: this covers P5c's need.

## What P5c (the scene evaluator) uses
- **A standalone `GraphDef`** with a Library, edited directly: no block, no undo, no
  notification. Its Pointer params are Weak, and its kernels use `useBlock`.
- **Incremental regeneration:** an edit is O(degree); the topology is rebuilt once per pass.
- **Generated node types** whose kernels use `paramBlock`, `queryBlock<Transformable>`,
  `library()` and `userData()`. P3's `objectQuery` takes a Library and a handle.
- **P3's `TransformState`** either as a payload socket with `equal` or as three inline sockets
  (mat4, quat, vec3). P5c chooses; the stand-in uses the payload, the harder case.
- **User graphs** as group nodes, connected through interior sockets. `NodeTypeFlags::
  OutputAdapter` and `GraphDef::forEachNode(flag)` list the adapters.
- **The apply phase:** one batched `evaluate` over all transform sockets, then `value()` or
  `lastGood()`, and `changedAt()` to tell SceneBvh what moved.
- **Time** through `setInput`.

A stand-in evaluator in the tests (about 150 lines: parents, a driver, an adapter, a
10,000-deep chain) is the check that this list is complete.

## Bindings (`bind/graph_facades.h`)
- **The gate changes:** `ForeignBindings` frames record the interface as well as the slot.
  `slotGate` matches (Command, slot) instead of the name alone.
- **Inside a kernel's frame** (the innermost frame is a `GraphKernel`), datapath reads,
  `inputGet`, `outputSet` and `outputGet` are Busy: reads would be dependencies the graph can't
  see, and the bags belong to an outer command. A foreign `Transformable` called from a native
  kernel is another frame, so it may read its own data.
- **Script node types:** `newNodeType(id)` and its builders, `registerForeignNodeType(ctx, def,
  kernelHandle, slots)`. `ForeignBindings` keeps the handle, as `keepFactory` does; the
  registry's kernel is non-owning, so the extensions may die in either order. `core.` and
  `graph.` are reserved.
- **In a kernel:** `nodeInput`, `nodeParam`, `nodeOutput`, and `nodePass(ctx, input, output)` for
  payloads and types scripts can't write.
- **Limit in v1:** script kernels work on scalars, vectors and strings, and pass payloads
  through. They can't read blocks. faberforge's TS geometry nodes need more (P6).
- **Editing:** `graphCreate`, `graphAddNode(ctx, graphPath, type, x, y)`, `graphRemoveNode`,
  `graphLink`, `graphUnlink`, `graphAddInterface`: each resolves the path and runs the command.
- **Evaluating:** `ScriptGraph` from `graphInstance(ctx, graphPath)`: `setInput`,
  `evaluate(output) -> ValueResult`, `errorText`. Hosts keep it in their session object.
- The TS layer gets `defineNodeType`.

## Serialization (last step, on P2's slots)
- The payload: a format version, the interface, the nodes (id, type name, label, position,
  params and literals by name, socket snapshot) and the links. Params go through P2's `bag()`,
  refs through `ref()`. Versions, topology and caches aren't saved.
- Unknown node types keep their params, because the value bytes are tagged.
- **Reading is bounded, and checked:** counts against the remaining bytes; ids in 1..2^52-1 and
  unique; links to known nodes; one link per input; one `graph.output`. A cycle or a recursion
  isn't an error (the evaluator reports it). A bad payload frees what it made.
- `duplicate` copies the def verbatim; P2's library rewrites its refs through `foreachRef`.
- `deserialize` makes new data, so a restored def has a new `serial`.

## Tests
- **`test_graph_random.cc`**, seeded, scaled by `COREDCC_TEST_SCALE`:
  - Random edits over several defs that use each other: nodes, links, params, literals,
    interface add, remove, move and setType, group changes, deleting and restoring defs, node
    types and conversions registered late, kernels that fail on some inputs, block edits with
    `notify`, `notifyAll`, `touch()` with no edit, host destroy and restore. From step 6, undo
    and redo.
  - After each batch two long-lived instances pull random sockets. Results (value, or error
    code and origin) must equal a **naive evaluator in the test** that shares no code with the
    engine. It memoizes within one evaluation, or diamonds make it exponential, and computes
    cycles as components of the fully expanded graph.
  - **The exact runs:** the test keeps its own record of what each kernel last read. Kernels
    whose inputs (by value), params or dependencies differ **must** run. Others **may** run only
    if something they read was touched or their resolved source changed since the last pull.
    Any other run fails the test. After a `touch()` that changes nothing, zero runs.
  - Undoing everything gives a def equal to the first one (ids and links), and redoing
    everything one equal to the last.
- **Mutation checks,** run and reported one at a time; each must fail a test: no stamp on undo;
  no source identity in the trace; no conversion chain; `changedAt` kept on an error
  transition; `changedAt` moved on an equal value; clearing the cache on every edit; `lastGood`
  read downstream; no liveness in a dependency; no pin for a replaced ref; eviction before
  success; no foreach dependency union; no `contentVersion` in the foreach trace; the key
  sampled at the end.
- **Lifetimes:** a payload after its Library (`get()` is null); Detached; an InHistory block
  destroyed while aliased, reviving its id meanwhile; instance after its def; a def block
  destroyed and revived under its id under an instance; GC after undoing a removed node, in quarantine mode, with the relations
  audit on.
- **Cycles and size:** a cycle and a kernel-free pass-through cycle made by an inner edit, pulled
  from every entry point with equal results; recursion made by writing the RefCell; 63, 64 and
  65 nested groups; a 40-level doubling graph (OutOfRange, under a second, and fast to link);
  a 100,000-node chain and a 100,000-node loop on a 1 MB stack.
- **Reentrancy:** every entry in the Busy list, natively and from a script; the interactive
  command stays open after a kernel's `undo`; disposing a ScriptGraph from its own kernel.
- **Foreach:** random tables, interior edits, interior block edits, unrelated edits (zero runs),
  tables over `maxCached`, duplicates, nested.
- **Scripts:** the fake dispatcher, and a TS node type in the wasm-st spike, also one that throws.
- **Fuzz:** `deserialize` on mutated payloads.
- **Benchmarks** (`bench_graph.cc`, not a ctest): a 10,000-node mat4 chain (full, one edit,
  unchanged); 1,000 instances of a 100-node group; foreach over 10,000 elements with one edited,
  and an unrelated edit. Targets, unchecked: an unchanged pull under 1 µs, re-verifying 10,000
  nodes after one edit under 2 ms, Release.

## Exit criteria
- The random test agrees with the naive evaluator for at least 1,000,000 operations in each
  compiler's Release build, and at the default scale in every gate.
- Every mutation check fails a test.
- A TS node type evaluates in wasm-st, and its errors reach the caller.
- The P5c stand-in works with only the API in "What P5c uses".
- wasm-mt builds and passes its tests. Benchmark results are recorded.

## Declared deviations from the architecture
- §7: no def-to-instances list and no `updateGeneration`. Stamping in setters, not `update` hooks.
- §7: socket types have no copy, hash or serialize operations, and there is no enum socket.
- §7 (P5b): no LRU; the cap bounds what is cached.
- §8a: `duplicate` has no IdMap (P2's deviation).
- §5: `setValue` posts the change before the `update` hook.

## Risks
- **P2's library piece and slots aren't final.** Steps 5 and 10 wait for them.
- **Traces cost memory:** about 40 bytes per input and 150 per output per instance.
- **Two sources of truth for sockets** (the snapshot and the real ones). The random test registers
  types late and deletes defs.
- **The budget is per root instance,** so a host with many roots has no overall limit.

## Out of scope
- Parallel and content-addressed evaluation, cyclic regions, simulation (§14).
- Lazy inputs, multi-input sockets, muting, reroutes, frames, copy and paste, making a group
  from a selection, enum sockets, per-instance overrides.
- Payloads made by scripts, and script kernels that read blocks (P6).
- The scene evaluator, adapters and generated transform nodes (P5c). A node editor UI.

### Minor, and what changed
- `lastEdit` sampled at the start; `setInput` and `retry` move the instance's count.

- Client aliases: the listener canonicalizes.
- Hostile payloads: the read checklist. Random ids remove the counter overflow.

### Rejected, and why
- **S8's "cancel before refuseNested" as a bug on master.** The branch is
  `if (open_ && !running() && slotDepth_ == 0)`, which is the same nesting test `refuseNested` makes.
  Skipping its stray-error test is deliberate, since `cancel` collects that error. Without graph
  evaluation there is no slot call outside the executor's frames that reaches it. It becomes a bug when
  step 1 adds evaluation, so step 1 adds the check and the regression test, which must open an
  EvaluationScope. A smaller real fault next to it is fixed there: `cancel` ignores a failed `Binding`.
- **S3's "counters never go back fails" needs per-node checks only.** The stronger change (random ids)
  also fixes the old StableRef that would name another node.
- **S11's "compare only 'failed by a cycle'".** It would have let wrong origins pass.
